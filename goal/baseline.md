# Baseline：真实伺服控制器的速度 / 功耗 / 面积 / 集成度

Status: **初版（2026-11-01）** — 只填了 C2000 F28P65x 一家（`doc/` 已收集的数据手册）。家族是否作主对标
仍待定（`research-plan.md` §5 第 4 问）；若改主对标为 RISC-V 应用处理器，本表整个重做。

所有出处都指 `doc/tms320f28p650dk.pdf`（ZHCSSI2D，2025-08 修订）的章节号。功耗是**推导量**，原始数据是
电流，换算过程在 §3 写明；其余未注明的格子标 `N/A + 原因`。

## 1. 器件与定位

| 器件 | 处理器 | 锁步 | EtherCAT | C28x 闪存 | 封装 | 出处 |
|---|---|---|---|---|---|---|
| F28P650DK9 | CPU1+CLA、CPU2 | 是 | 是 | 1.28 MB | NMR nFBGA169，9×9 mm | §1 特性、器件比较 |

选型取两个点：**DK8（双核 + CLA）** 与 **SK7（单核 + CLA）**——后者是"少一颗 CPU"的对照，用来分离
"多核"与"CLA 加速器"各自的贡献。

对我们的意义：**它们的"速度"是每周期一条指令 + 硬件浮点/三角函数**。我们在 RV32I 上跑同一套 f32 IK 是
软浮点（前面实测 riscv32im 能把计算压到 630k 拍/tick，说明算术占了 ~54%）。

## 3. 功耗（推导）

数据手册给的是电流（§6.5.1 启用 VREG / §6.5.2 禁用 VREG）。换算取 §6.4 的标称电压：
`VDD = 1.2 V`，`VDDIO = 3.3 V`，`VDDA = 3.3 V`。VDDIO 的 3.3 V 是假设（手册给的是范围），已标注。

外部供电（§6.5.2，典型值，Vnom 30 °C）：

| 模式 | IDD（VDD 1.2 V） | 推导功率 | MIPS/W |
|---|---:|---:|---:|
| 单 CPU 活动 | 190 mA | 1.2×190 + 3.3×4.2 + 3.3×18.6 ≈ **0.30 W** | 400 MIPS → **≈1,330** |
| 双 CPU 非锁步 | 270 mA | ≈ **0.40 W** | 600 MIPS → **≈1,500** |
| 双 CPU 锁步 | 330 mA | ≈ **0.47 W** | 600 MIPS → ≈1,280 |

（VDDIO 电流在外部供电时只有 4.2 mA；VDDA 18.6 mA 不随核数变。）

## 6. 与本平台的可比性：三个缺口

1. **我们还没有功耗/面积。** RTL 可综合（`just sta` 出网表与面积），但没有映射到具体 PDK，也没有功耗估算；
   板上是 Artix-7（FPGA），不能代表 ASIC。→ 要补这一维，得跑一次带 PDK 的综合 + 功耗估算，或明确只用
   "LUT/FF 数量"作为代理。
2. **频率不可直接比。** C28x 200 MHz + FPU64/TMU vs 我们 25/50/100 MHz RV32I + 软浮点。可比的只有
   **每任务时间**（`robot_arm` 一个控制 tick），而这需要同一份算法两边都跑——目前只有我们这边有。
3. **集成度不可比。** C2000 的集成度是"把电机控制外设做进片内"；我们的平台把外设放在片外总线后面
   （这正是被建模的延迟来源）。两者是两种取舍，比较时必须说明这是设计选择而非优劣。

## 7. 待办

- 补第二个家族（至少一个 CPU-only / 一个带加速器的 RISC-V 或 Cortex-M 器件），否则"两个 baseline"不成立。
- 若确定 C2000 为主对标：把 §2 的 MIPS 换算成**每 tick 预算**（16 ms × 200 MHz = 3.2M 周期），
  与我们的 1.364M 拍/tick 直接对照——这是目前唯一一把公平的尺子。
